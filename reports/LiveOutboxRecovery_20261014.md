# 未送信成果物の点検と復旧前の確認

公開通信が途中で失敗しても、監視が保存した内容を再生成せず確認するための手順です。点検ツールは読み取りだけで、Gitのfetch・push・checkout、予測、観測、学習、キューの削除・書き換えを行いません。

## 使用する保存済み成果物

- Live Permanent: `keibaai-live-outbox-実行ID`。
- Monitor Health: `keibaai-monitor-health-outbox-実行ID`。
- 保管期間は14日。`state.json`と`blobs/`が含まれます。Runnerが失われて成果物保存も実行できなかった場合まで保証するものではありません。

GitHubの実際の実行ページで失敗時刻、開催日、成果物名を確認してから取得します。過去の例や試験用データを本物の記録として公開しません。ZIPの展開後に、state.jsonとblobsが同じフォルダにあることを確認します。

## 点検する

公開先の最新履歴を取得済みの、監視とは別のGitリポジトリを用意します。必要なfetchは事前にそのリポジトリで実施し、点検コマンド自体ではネットワーク通信しません。

```bash
python production/inspect_live_outbox.py \
  --outbox /absolute/path/to/unpacked-outbox \
  --repo /absolute/path/to/comparison-checkout \
  --ref origin/main
```

結果はJSONで標準出力に表示します。比較先を最初に固定コミットへ解決するため、点検途中にmainが進んでも、ファイル間で異なる公開版が混じりません。保存時のソースコミットと比較先の関係も示します。終了コード0は保管された未送信内容が比較先に含まれ、追加の注意事項がない状態です。1は要確認、2は点検そのものを完了できない状態です。いずれも復旧の実行や承認ではありません。

| 状態 | 意味 | 次の対応 |
|---|---|---|
| published | 保存時と同じバイト列が比較先にある | 応答消失の可能性を確認。再生成しない |
| represented | JSONの形式差や合流後の内容として比較先に含まれている | 別レースや新しい終了状態も保たれている。差分を確認 |
| unpublished | 比較先にファイルがない | 元の実行・時刻・内容を確認して復旧候補を整理 |
| review_required | 公開先と内容が異なる | どちらの更新が新しいか確認。通常予測を機械的に戻さない |
| conflict | 最初の予測等と競合し、既存公開処理が拒否する | 先に公開された記録を保持。別レースの正常な保存も個別に確認 |
| invalid | 内容欠落、指紋不一致、不正JSON等 | その内容を復旧に使わず、元の成果物・実行を確認 |

`pendingFiles`はマニフェストに残った数で、未公開と確認できた数とは違います。送信は成功して応答だけ失われた場合にもpendingは残ります。`counts`を使って区別します。点検はpendingを消しません。

保存時に取り込めなかった内容は`captureErrors`、保管された指紋付き内容の欠落・不整合は`archiveErrors`へ分けて表示します。キューが空でも、これらがあれば正常な全件保存とは判断しません。

## 日付をまたいだ場合

開催日と点検日が異なれば注意事項を表示します。既存の公開処理は開催日が変わった通常再送を拒否します。このツールで日付制限を回避することはできません。保存済みの研究記録の復旧は、通常のRaceDataや信号を古い開催へ戻す操作と分け、対象ファイル・当時の時刻・学習と入力の指紋・現在の公開内容を照合したうえで検討します。

今回は復旧のための書き込みコマンドを追加していません。本物の未送信成果物がまだ存在しない段階で、自動復旧を実行したり過去の予測を付け足したりしません。

## 確認範囲

13件の新規試験で、実際の一時Gitリポジトリと保存マニフェストを使い、未公開、応答消失、同日の別レース合流、最初の予測競合、通常更新の差分、日付変更、指紋・JSON・パス・世代形式の不正、シンボリックリンク、ソース不明、取得失敗、古い開始状態から終了状態への合流、実レース行と説明文の維持を確認します。ファイル全体の指紋を点検前後で比較する試験により、作業ファイル・Gitメタデータ・成果物の不変を確認します。

アプリ画面には変更がなく、配布KeibaAI.zip v9の再配布や更新は不要です。実際の開催での保存・結果照合、次の通常監視の状態通知、端末操作の確認は別の未完了項目です。
