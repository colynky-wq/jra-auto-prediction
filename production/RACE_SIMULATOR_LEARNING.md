# RaceSimulator v0.2 継続改善

発走前のシミュレーションを固定し、確定結果と照合します。過去レースへの当てはめだけでは新設定を採用しません。学習用レースと、その後に行われる採用判定用レースを分けます。

## 運用

1. 既存のライブ監視で正式10分前の入力を得ると、現行モデルと検証中モデルを同じ入力・乱数種で実行します。開始30秒前までに計算を始め、発走前に保存を完了できた記録だけを残します。
2. `reports/YYYYMMDD/race_simulator_v02/<raceID>.json` に入力、シミュレーション結果、再生フレーム、設定、モデルとエンジンの識別子を保存します。最初の記録を上書きしません。発走前の最初のGitコミットを確認できないものは学習から除外します。
3. 毎日17:17・20:17日本時間のGitHub Actionsで、`ResultData.json` の結果を照合します。GitHubの実行待ちによる遅延はあり得ます。結果未確定、出走取消、馬番・馬名の不一致、履歴やモデルの不整合は保留します。
4. 30レース・2開催日以上の有効記録から、直近最大60レースを使って候補を1つ作ります。候補を固定した後に行われるレースで、現行と候補の予測を両方保存して検証します。
5. 学習に使っていない、その後の30レース・2開催日以上を検証します。芝・ダートと4つの距離帯それぞれで6レース・2開催日以上に達した最初の区切りで一度だけ判定します。必要件数に達するまで最大120レースを蓄積し、その時点でも条件別件数が足りなければ見送ります。区切りは結果の良し悪しで選びません。不採用になった候補を、都合のよい後続レースで再判定しません。

従来のレース後に生成された表示用シミュレーションは、発走前予測の実績として数えません。導入時点では検証実績0件、現行設定のまま開始します。

## 評価と採用条件

小さい誤差ほどよい総合損失で比較します。勝者のBrierスコア50%、頭数で正規化した予想着順の平均絶対誤差25%、勝ち時計の相対誤差10%、前半600mの相対誤差10%、各馬の上がり600mの相対誤差5%です。欠測を0扱いせず、利用可能な指標の重みを再正規化します。同着の勝者には実績確率を均等に配分します。

候補は次の条件をすべて満たした場合だけ採用します。

- 現行に対して総合損失が2%以上改善する。
- レースごとの対応を保ったブートストラップ2,000回で、改善幅の片側95%下限が正になる。
- 勝者のBrierスコアと着順誤差が悪化しない。
- 検証レースの60%以上で、検証済みの公式勝ち時計と正確な前半600mを照合できる。
- 時計・前半600m・上がり600mの平均相対誤差が各0.2パーセントポイントを超えて悪化しない。
- 検証期間の後半でも総合損失が悪化しない。
- 芝・ダート、および短距離（1400m以下）、マイル（1401〜1800m）、中距離（1801〜2200m）、長距離（2201m以上）の各区分で必要件数を満たす。区分別の総合損失が2%を超えて悪化せず、Brierスコアと正規化順位誤差も各0.02を超えて悪化しない。十分な件数がある芝・距離帯の組合せも同様に検証する。

候補には判定方針も固定保存します。途中で判定基準が変わった場合は同じ候補をそのまま採用しません。

## 採用後の監視と旧設定への復帰

新設定の採用後は、直前の旧設定も発走前に同じ入力・乱数種で並行実行します。レース後に旧設定の予測を作り直すことはありません。新旧の両方を保存できた、その後の30レース・2開催日以上を1区間として比較します。判定に使う区間は重複させません。

新設定の総合損失が旧設定より5%以上増加し、対応のあるブートストラップの下限が正、かつ区間後半でも悪化している場合に旧設定へ戻します。必要件数のある条件別区分で同じ悪化を確認した場合も復帰します。全体と複数区分を調べる際は検定数に応じて下限の判定水準を補正します。

単発の不的中では戻しません。旧設定へ戻した理由・比較対象・モデル識別子を変更できない判定履歴として残します。同じ区間を繰り返し再判定したり、新しい結果がないまま復帰直後に同じデータで再学習したりしません。監視方針も採用時に固定します。

採用後の最初の区間を確認するまでは次世代候補の作成を待ち、その後は監視を続けながら次の候補を検証できます。

## アプリ内の確認

「展開シミュ」→「記録状況・継続改善」で確認できます。

- 各レースを、保存待ち／保存済・公開確認待ち／結果待ち／結果照合済み／照合保留／保存漏れ／保存失敗／導入前・対象外に分けます。
- 予定一覧がある日は、RaceDataに未取得のレースも一覧に含めます。予定一覧がない場合は、開催全体の保存率が未確定と明示します。
- 日付を切り替えて直近30開催日の記録を確認できます。通信失敗時に成功表示を残さず、取得失敗を表示します。
- 採用中・検証中の設定、条件別の件数・誤差、採用後の監視と復帰履歴を表示します。
- 実開催の保存と結果照合が一巡するまでは「確認はこれから」と表示します。テストの成功を実開催の実績には数えません。

公式の前半区間が650mなどの場合、600mとして比較しません。実際のコーナー通過順は結果とともに保存しますが、距離対応が分からないコーナーをシミュレーターの25%・50%地点などに置き換えて評価しません。

## 変更範囲

更新対象はシミュレーターの速度倍率（0.90〜1.10）、独立した過去成績の強さの倍率（0.5〜1.5）、脚質による速度差の倍率（0.5〜1.5）です。入力する過去成績・脚質履歴は開催日より前までのものに限ります。履歴の最終日を確認できないデータは使いません。

予測AIの勝率、オッズ、人気、馬券候補を走行計算や設定探索の入力には使いません。既存の正式予測や馬券ロジックは変更せず、自動購入は行いません。シミュレーターの新設定は、次に保存する発走前シミュレーションから適用します。保存済みの再生内容は変わりません。

## 記録と確認方法

- [現在の状況](../reports/RaceSimulatorLearning.md)
- `RaceSimulatorLearning.json`: 採用中・検証中モデル、実績数、保留理由、方針、判定履歴。
- `RaceSimulatorRecordingStatus.json`: アプリ用のレース別状態・日付別履歴・予定一覧の有無・実開催の確認状況。
- `reports/YYYYMMDD/race_simulator_attempts.json`: 保存試行の状態と理由。
- `research/race_simulator/state.json`: 採用中・検証中モデルの参照。
- `research/race_simulator/models/<modelID>.json`: 変更できない候補設定、学習レース、学習締切、目的関数。
- `research/race_simulator/decisions/<SHA256>.json`: 検証対象、誤差、信頼下限、採用・不採用の理由。
- `reports/YYYYMMDD/race_simulator_evaluation/<raceID>/<SHA256>.json`: 予測と確定結果の照合。公式結果が修正されたら別記録として保存し、同じレースを重複して数えません。

```bash
# ライブ監視が通常呼び出す保存処理。過去の発走時刻には遡れません。
python3 production/race_simulator_learning.py capture

# 全コミット履歴のあるチェックアウトで実行する結果照合・学習・採用判定。
python3 production/race_simulator_learning.py cycle

cd production
python3 -m unittest test_race_simulator_v02 test_race_simulator_learning test_race_simulator_operations test_live_bundle_publisher
```

エンジン・入力変換・設定定義が変わると、旧エンジンで作成した記録・モデルを新しい検証に混ぜず停止・保留します。変更時は旧記録を残し、新バージョンの初期設定と新しい発走前記録から検証を始めてください。評価方法を変える場合も目的関数バージョンを更新します。

採用判定は将来の精度や回収率の改善を保証するものではありません。記録と別レースでの比較を積み重ねるための仕組みです。
